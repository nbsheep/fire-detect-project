# 接入无人机 · 自动巡航火灾巡检（对准拍摄 + 报告）

把本仓库的离板火/烟检测接到 DJI M3E 无人机上：**无人机自动巡航**，电脑端对实况画面做 YOLO 火/烟检测，**确认火情后自动把云台对准火源、拍照、打 GPS、写入巡检报告**。无人机只负责巡航，检测和拍摄全在电脑端完成。

> 方案定位：**离板（PC 端）**。检测跑电脑，不跑无人机；后端不接管飞行轨迹，只做监视 + 云台/相机/打点。

---

## 一、前置条件

| 项目 | 要求 |
|------|------|
| 无人机 + RC Pro | 开机，Drone_test APK 已装且在**自动化飞行页** |
| 网络 | PC 与 RC Pro 在**同一局域网**（建议同一路由器，避免 AP/客户端隔离；参考 [`Desktop/DJI无人机RTMP连接指南.md`](../../../Desktop/DJI无人机RTMP连接指南.md)） |
| 连通性 | PC 能 `curl http://<RC_PRO_IP>:8080/api/status` 拿到 JSON |
| 飞控准备 | 已在 RC Pro 上设置好航点并 `start_cruise`（无人机**正在自动巡航**） |
| 检测环境 | `anaconda3\envs\fire-detect`（torch CUDA + cv2 + ultralytics + requests + jinja2），模型 `models/best.pt` 存在 |

RC Pro 默认 IP：`10.225.57.15`（可用环境变量 `RC_PRO_IP` 覆盖）。

## 二、运行顺序（直连模式）

**① 无人机会先开始自动巡航，② 然后再跑本程序。** 顺序颠倒会导致程序发现云台/相机不可用而只能检测、无法拍摄。

```bash
# 进入检测环境
C:/Users/nice/anaconda3/envs/fire-detect/python.exe --version

# 启动巡检（默认直连 http://10.225.57.15:8080/api/video）
C:/Users/nice/anaconda3/envs/fire-detect/python.exe scripts/fire_patrol.py
```

无人机会自动巡航 ✓ → 程序开始拉 MJPEG 实况 → YOLO 逐帧检测 → 连续 `TRIGGER` 帧检到火（默认 5 帧）→ 打印报警 → **云台对准 + 拍照 + 读 GPS + 写报告**。

**窗口激活时按 `q` 退出**（或 `Ctrl+C`），退出时总是生成 `runs/reports/inspection_*/events.csv` 与 `report.html`。

### 常用环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `RC_PRO_IP` | `10.225.57.15` | RC Pro 局域网 IP |
| `SOURCE` | `http://<IP>:8080/api/video` | 视频源；也可用 `rtsp://127.0.0.1:8554/live/drone`（需 ffmpeg→MediaMTX） |
| `CONF` | `0.35` | 检测置信度阈值 |
| `TRIGGER` / `RELEASE` | `5` / `15` | 报警/解除所需的连续帧数 |
| `AIM_ON_FIRE` | `1` | 发现火→云台对准（`0` 关闭） |
| `CAPTURE_ON_FIRE` | `1` | 对准后拍一张（`0` 关闭） |
| `SHOW` | `1` | 实时预览窗口 |

### 本地演练（无无人机）

```bash
# 用仓库自带的样例视频跑通"检测→去抖→报警→报告"链路（不会连无人机，自动跳过云台/拍照）
SOURCE=samples/test.mp4 SHOW=0 scripts/fire_patrol.py
```

## 三、RoboNIX 原语路径（可选）

上面的直连方式不依赖 RoboNIX，最稳。若想让 RoboNIX 也能调这些能力，用 `rbnx`：

```bash
# 1. 启动 RoboNIX（会加载 drone_bridge driver）
rbnx boot

# 2. 看有哪些 drone 原语
rbnx caps | grep drone

# 3. 查完整状态（含 GPS / cruiseActive）
rbnx call robonix/primitive/drone/state

# 4. 手动对准 / 拍摄
rbnx call robonix/primitive/drone/gimbal_velocity --args '{"vpitch": 0, "vroll": 0, "vyaw": 30, "duration": 1.0}'
rbnx call robonix/primitive/drone/camera_capture

# 5. 自然语言
rbnx ask "把无人机相机云台向右转 30 度持续 1 秒并拍一张照"
```

> 取舍：**直连** → 少一层依赖，适合一键巡检脚本；**rbnx** → 让 RoboNIX 掌握全部能力，后续想接入 `rbnx chat`/其它 Skill 时用。两者都走同一套 `/api/*`，可二选一，不必同时开。

## 四、安全须知（务必先读）

1. **必须在室外空旷、无遮挡处飞行**，场地内有其他人看护，飞机始终在视线内。
2. **首次先小步验证**：先手动小角度测云台/相机，再跑本程序；确认方向映射正确（`yaw_right` 会让火往画面里靠等）。
3. **云台与相机只在无人机「正在巡航」时可用**。本程序逐帧读取 `/api/status.cruiseActive`，非巡航时**自动跳过**对准与拍摄（只做检测与记录），不会越权动作。
4. **本程序绝不发送飞行控制命令**：不涉及 takeoff / land / move / rth，不改变无人机航迹。它只调用云台、相机、GPS 打点三类接口。
5. **发现火只做「对准拍摄 + 报告」，不会自动返航。** 需要处置仍由飞手判断（远处可手动触发 `rbnx call robonix/primitive/drone/rth` 或用遥控器）。
6. 视频流是实时画面，网络抖动会丢帧/延迟；若 MJPEG 延迟明显，改用 MediaMTX→RTSP 方案（见 `../../../Desktop/DJI无人机RTMP连接指南.md`）。
7. 无人机安全高于一切：**一旦异常，先用遥控器接管**，本程序只管检测与拍摄，不是飞控。

## 五、代码结构

| 文件 | 作用 |
|------|------|
| `scripts/fire_patrol.py` | **主巡检程序**：拉流 + 检测 + 去抖 + 云台对准/拍照/GPS/报告 |
| `scripts/gimbal_aim.py` | **云台对准控制器**：把火框偏移映射成离散步进（pitch/yaw），守卫巡航 |
| `scripts/reporter.py` | 巡检报告（截图 + CSV + HTML），**复用** |
| `scripts/alarm.py` | 去抖器（连续 N 帧才报警/解除），**复用** |
| `scripts/rtsp_detect.py` | RTSP 流检测 + 火势预测，**复用** |
| `drone_bridge/` | `DroneClient` HTTP 客户端（封装 `/api/gimbal` `/api/camera` `/api/capture_gps` `/api/status`） |
